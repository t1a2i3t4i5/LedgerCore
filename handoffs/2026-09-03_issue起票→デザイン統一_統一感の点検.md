# 引き継ぎ: issue 起票（2人利用・アイコン） → デザインの統一感の点検

- 作成日: 2026-09-03
- 次のセッションの目的: LedgerCore の画面デザインに「統一感がない」と感じている点を特定し、直すべきものを切り分ける。まだ具体的にどの画面が気になっているかは未特定なので、そこから始める。

## 引き継ぎ先がまず読むべきファイル

- `docs/design-notes.md` — デザイン上の約束・理由・過去の事故の**正本**。ここに書かれた判断（意図的な不揃いを含む）を「統一感がない」と誤認しないために、変更提案の前に必ず読む
- `lib/theme/ledger_tokens.dart` — 補助色・角丸・影・書体トークン。何がトークン化されていて、何がされていないかが一目で分かる
- `lib/theme/ledger_theme.dart` — `ColorScheme` と Material コンポーネントテーマ
- `CLAUDE.md`「破ると静かに壊れる約束」 — テーマ・書体・ヘッダ・グラフ色の約束が索引されている

## これまでの経緯（要点）

1. このリモート環境（Claude Code on the web）とローカルの違いを確認した
2. 「2人で使う用のアプリにしたい」という要望を issue 化した（下記 3 件）

## いま分かっていること / 決まったこと

### 環境の制約（重要）

- **リモート環境には Flutter / Dart SDK が無い**（`which flutter dart` が空、`~/.pub-cache` 無し）。`flutter test` / `flutter analyze` / `dart run build_runner build` / `dart format` がすべて動かない
- `.claude/settings.json` の PostToolUse フックが `.dart` 編集ごとに `dart format` を呼ぶが、コマンドが無いので**失敗するだけで整形されない**
- `gh` CLI も無い（GitHub 操作は MCP ツール経由）。`.claude/settings.json` の `Bash(gh pr *)` 許可は効かない
- **アプリを起動して見た目を確認できない**。デザインの判断に実画面が要るなら、ローカルで作業すること

### デザインの現状（この会話で調べた事実）

- **色リテラルの直書きは無い。** `lib/screens` と `lib/widgets` に色リテラルは `lib/widgets/chart_palette.dart` のみ（グラフ用パレット。CLAUDE.md が定める正しい置き場所）。ここは違反していない
- **`LedgerTokens` に余白（spacing）のトークンが無い。** 持っているのは補助色・角丸（`cardRadius` / `cardRadiusLarge` / `pillRadius`）・影・書体だけ。余白は各画面が `SizedBox(height: …)` で直書きしており、`lib/screens` + `lib/widgets` に 2 / 4 / 8 / 12 / 16 / 24 の 6 種が計 50 箇所ある（内訳: 8 が 20 件、16 が 15 件、12 が 8 件、4 と 24 が各 3 件、2 が 1 件）。**「統一感がない」の最有力候補**
- **確認ダイアログが 3 画面にインラインで重複している。** `categories_screen.dart:33, 79` / `members_screen.dart:32, 85` / `transactions_screen.dart:67` がそれぞれ `AlertDialog` を直接組み立てている。カテゴリとメンバーの編集ダイアログはほぼ同一の実装
- **ヘッダの 4 系統は意図的な使い分け。** `PageHeader` / `PinnedBackPageHeader` / `MonthSelector` / 取引追加の専用 3 分割ヘッダがあるが、これは CLAUDE.md に「ルートタブは本文と一緒にスクロール、push 先は戻る導線を残す `PinnedBackPageHeader`」と明記された約束。**統一の対象にしないこと**
- **ライト専用。** `main.dart` は `themeMode: ThemeMode.light` 固定で、ダークテーマは対象外（判断は `docs/design-notes.md`）
- 過去のデザイン刷新は #90 を親に #91〜#101・#112・#113・#121・#122 で実施済み（すべて closed）。design-notes.md にその判断が残っている

## 引き継ぎ先にやってほしいこと

1. **まず本人に「どの画面のどこが気になるか」を聞く。** 「統一感がない」は感覚が起点なので、こちらの推測（余白・ダイアログ）から入らず、実際に見て引っかかった箇所を特定する
2. 挙がった箇所について、`docs/design-notes.md` に**意図的な判断として既に記録されていないか**を先に確認する。記録があるなら、それは不揃いではなく約束
3. 記録が無いものについて、上の「デザインの現状」の候補（余白トークンの不在、ダイアログの重複）と突き合わせる
4. 直すと決めたら、`docs/git-workflow.md`「issue の運用」の基準で issue にするか直接実装かを判断する。テーマ層に手を入れるなら影響が全画面に及ぶので issue 向き
5. 実装するならローカルで。リモートでは `flutter test` も見た目の確認もできない
